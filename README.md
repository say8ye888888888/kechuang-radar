# 工银科创雷达

面向银行客户经理的科技企业授信预审工作台。它服务第 17 届“工行杯”科技金融方向：在进件前判断一家科技企业该进科创专利贷、科技信用贷，还是先补充调查、先核权属。

评分卡给出结论，知识图谱保留证据，说明文字只复述证据包里已经存在的事实。演示环境不调用外部大模型，也不输出授信额度。

## 本地运行

```bash
npm install
npm run dev
```

## 当前系统链路

页面和 API 共用同一套服务层：演示企业数据 → 证据与材料状态 → 五维科技预评分 → 产品规则 → 冻结 EvidencePack → 本地模板报告。前端页面直接调用服务层，外部客户端可以调用同一服务暴露的 Route Handler。

```text
GET  /api/health
GET  /api/methodology
GET  /api/companies?q=半导体&product=patent-loan
GET  /api/companies/{id}
GET  /api/companies/{id}/graph?depth=2
POST /api/evaluations
GET  /api/evidence/{id}?companyId=chengchuan
```

`POST /api/evaluations` 接收 `{ "company": CompanyInput, "asOf": "YYYY-MM-DD" }`，只做即时评估，不写入数据库。当前仓库使用六家 DEMO 企业的只读数据仓库，便于比赛演示；后续可在不改变服务层和 API 契约的情况下替换为 SQLite/PostgreSQL。

外部提交的权利只有在 `verificationState=verified` 且关联的 `patent/risk` 证据带有 `sourceUrl` 时才会进入已核验路径；单独自报 `verified` 会降为待核验。`asOf` 只接受不晚于当前演示数据快照（2026-10-05）的日期，并会裁剪评估时点之后的权利和材料，避免未来信息泄漏到历史快照。

评估详情接口和 POST 接口统一返回 `{ data: { evaluation, validation } }`；列表接口返回 `{ data: { items, count } }`。`GET /api/evidence/{id}` 在编号跨企业重复时返回 409，带 `companyId` 可定位到单一评估。

评估结果明确区分科技预评分和偿债材料状态。缺少完整偿债材料时，结果范围为 `innovation-only`，只对技术、持续性、行业和风险维度重新归一化计分，产品结论为补充调查，不推荐专利质押贷或科技信用贷。所有三件发明、八年剩余保护期和分数线均为带版本号的演示规则，不代表工行正式制度。系统不输出违约概率、贷款额度或专利估值。

报告只接收冻结的 `EvidencePack`。证据编号、评估时点、数据快照、评分版本和规则版本随结果返回；报告引用缺失或数字不一致时应回退到确定性模板。规则证据编号在演示样本间可能重复，查询规则证据时应带 `companyId`，系统会拒绝返回含糊的首条记录。

浏览器打开 [http://127.0.0.1:47281](http://127.0.0.1:47281)。

建议演示顺序：澄川半导体（科创专利贷）→ 织衡软件（科技信用贷）→ 岚析生物（技术分高但仍暂缓）→ 方法与边界。

## 样本说明

六家企业都是虚构主体，权利编号以 `DEMO` 开头。分数用来展示规则，不对应真实公司，也不构成授信、估值或投资意见。

## 评分与规则

- 技术竞争力 30%，创新持续性 20%，行业前景 15%，财务能力 20%，风险可控 15%
- 财务证据完整时才进入偿债维度和贷款产品规则；缺失时仅输出 `innovation-only` 科技预评分并转补充调查
- 可质押发明：演示默认要求有效、权属清楚、状态为 `verified`、无年费风险、剩余保护期不少于 8 年；`reported` 只表示有来源记录，仍会进入待核验路径
- 企业级核心权利争议会停止产品推荐；非核心单项瑕疵只从质押候选中排除

以上阈值和口径均为版本化演示配置，不是工行正式授信制度。六家 DEMO 样本中的偿债字段也是合成演示材料，接入真实企业时必须替换为经授权、可核验的数据。

产业档位是人工规则表，不是预测模型。接入真实数据时，先做一个城市、一个产业的约 30 家企业，字段与演示中的权利清单一致。
